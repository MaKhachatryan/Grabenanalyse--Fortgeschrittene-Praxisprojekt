# 2. Corrected Function
get_model_stats <- function(model, name) {
  
  # A. Model Health
  # Use nuts_params from brms to get divergences
  nuts <- tryCatch(nuts_params(model), error = function(e) NULL)
  if(!is.null(nuts)) {
    divs <- sum(subset(nuts, Parameter == "divergent__")$Value)
  } else {
    divs <- NA # Handle cases where model crashed
  }
  
  # FIX FOR RHAT ERROR:
  # We extract Rhats directly from the rhat() function in brms namespace
  # If that fails, we return NA
  r_values <- tryCatch(brms::rhat(model), error = function(e) NA)
  rhat_max <- max(r_values, na.rm = TRUE)
  
  # B. Model Fit (WAIC)
  waic_val <- tryCatch(waic(model)$estimates["waic", "Estimate"], error = function(e) NA)
  
  # C. Key Biological Coefficients
  # We use fixef() which is standard for brms
  fix <- fixef(model)
  
  # Extract Male-Male Effect (Adjust string "XYMXY" if your summary shows differently)
  # using grep to find the row that matches "XYMXY" even if the name varies slightly
  mm_row <- grep("XYMXY", rownames(fix))
  beta_MM <- if(length(mm_row) > 0) fix[mm_row, "Estimate"] else NA
  
  # Extract Subadult Effect
  sub_row <- grep("subadult", rownames(fix))
  beta_Subadult <- if(length(sub_row) > 0) fix[sub_row, "Estimate"] else NA
  
  # D. Random Effect Variances
  # Safely extract variances
  vars <- VarCorr(model)
  
  # Extract Individual Variance (mm function)
  # Note: The name is usually 'mmindividual1_idindividual2_id' but might vary
  sd_ind <- NA
  if("mmindividual1_idindividual2_id" %in% names(vars)) {
    sd_ind <- vars$mmindividual1_idindividual2_id$sd[1]
  }
  
  # Extract Tomb Variance
  sd_tomb <- NA
  if("mmtomb1tomb2" %in% names(vars)) {
    sd_tomb <- vars$mmtomb1tomb2$sd[1]
  }
  
  return(data.frame(
    Model = name,
    Divergences = divs,
    Max_Rhat = round(rhat_max, 3),
    WAIC = round(waic_val, 1),
    Est_MaleMale = round(beta_MM, 2),
    Est_Subadult = round(beta_Subadult, 2),
    SD_Ind = round(sd_ind, 2),
    SD_Tomb = round(sd_tomb, 2)
  ))
}

Compare between with and without bone quality

Logic of this sensitivity analysis:

Because “Tomb” \(\rightarrow\) “Preservation” \(\rightarrow\) “Observed kinship”, therefore we added bone_quality to the model before to control for the path between “Tomb” and “Kinship”. So that the relationship between Tomb and Kinship not just an artifact of preservation.

But does this “preservation bias” really exist (and need to be controlled by the bone quality)? Or was it already taken care of from when we filter 15k threshold (only qualified sample)?

\(\Rightarrow\) Sensitivity analysis:

  • Bias: If when we remove bone_quality, the “Same Tomb” coefficient shifts wildly because it suddenly has to absorb the preservation bias. Then we still need to add bone_quality in the model.
  • No bias: When we remove bone_quality, the same_tomb coefficient stays stable. Then we can just delete bone_quality (which makes the model simpler and easier to interpret).

Add tomb variables

Additional variables:

  • sample_success_min:
    • The effective information for the pair is given by the minimum of the 2 tomb sizes. Because the larger sample can not compensate for the lack of information on the smaller side.
    • Interpretation/Intuition: Pairs that has higher sample success are more likely to be related
  • analysed_ind_min:
    • Interpretation/Intuition: Pairs that are evaluated in a higher analysed samples (richer context) are more likely to be related
    • This accounts for contextual sampling depth
    • Concern: Wouldn’t this cause multicollinearity with sample_success_min? Check: cor = 0.70 => pretty high. Support a sensitivity check with dropping sample_success_min
  • length_of_use_absdiff: account for temporal context
    • Interpretation/Intuition:
      • If negative: tombs has smaller different length of use are more likely to be used to bury the related poeple (so like they have the same temporal context so they are more likely to be related).
      • If positive: not so intuitive
